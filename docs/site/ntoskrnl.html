Compatibilidade com o Windows 10

Exports do ntoskrnl

Dos 3.070 nomes que o ntoskrnl.exe do Windows 10 exporta para os drivers, quantos o kernel do OpenNT também exporta.

O que é contado: um nome da lista do Windows conta quando aparece na tabela de exports do kernel do OpenNT. Cada nome exportado tem uma rotina ou variável do OpenNT por trás, mas ter o nome não garante que ela trate todos os casos que o Windows trata. Referência: ntoskrnl.exe do Windows 10 22H2 (build 19045).

    Para começar

    O que são exports e o que este número diz

    O que é um export?

    O ntoskrnl.exe é o kernel do Windows. Um driver (.sys) não traz o kernel junto: na sua tabela de importação ele lista, pelo nome, as rotinas do kernel que vai chamar, como IoCreateDevice para criar um dispositivo ou ExAllocatePoolWithTag para alocar memória. Essas rotinas, e algumas variáveis globais como PsInitialSystemProcess, são os exports do kernel.

    O que o número diz, e o que não diz

    Diz quantos nomes da lista do Windows o kernel do OpenNT também exporta. Ao carregar um driver, o kernel procura cada nome importado; se um único nome faltar, o driver não carrega.

    Não diz se cada rotina se comporta exatamente como a do Windows. Isso é verificado pelos testes automáticos. Os drivers do Windows que já carregam e rodam nos testes automáticos usando estes exports: hal.dll, i8042prt.sys, kbdclass.sys, mouclass.sys, wmilib.sys e WppRecorder.sys, cng.sys, ci.dll (Code Integrity), watchdog.sys.

    Fontes

    De onde vêm os números

    • Windows: a tabela de exports do ntoskrnl.exe real (arquivo 10.0.19041.6456), lida pelo próprio gerador e guardada em docs/status/ntoskrnl-exports.def; só os nomes, nunca o binário. Um export é variável quando aponta para uma seção sem permissão de execução. A tabela tem ainda 23 entradas só por número (ordinal), fora da conta.
    • OpenNT: os nomes da tabela de exports do kernel, que vêm de kernel/src/ntos/init/export_names.rs (funções) e kernel/src/ntos/mm/kernel_data_layout.rs (variáveis), os mesmos arquivos que o xtask usa para montar a tabela de exports do PE do kernel.
    Gerado por cargo xtask status a partir do código do repositório, de docs/status/components.toml e da lista de exports do ntoskrnl.exe. Não edite estas páginas à mão: edite os dados e gere de novo.
