Plano do kernel

Módulos do kernel

Quanto do plano de código do kernel já foi escrito, subsistema por subsistema.

Um módulo é uma unidade planejada de código do kernel, com nome no formato pasta/nome: por exemplo, ntos/ob/handle_table é a tabela de handles do gerenciador de objetos. Um módulo conta quando o arquivo Rust dele existe. Isso mede quanto código já foi escrito, não se ele funciona; para isso, veja os testes e os componentes.

O que significa cada estado

Com códigoo arquivo Rust do módulo existe no repositório.
Parcialo arquivo existe, mas só uma parte do módulo foi escrita; o motivo aparece ao lado.
Pendenteo arquivo ainda não existe.
Fora da contamódulo descartado (diagnósticos e experimentos, por exemplo); não entra nas contas.

Autoteste: sim quer dizer que uma suíte de kernel/src/ntos/test/ importa o arquivo do módulo diretamente. Os demais podem ser exercitados de forma indireta pelos testes de boot. A barra de cada subsistema mostra os módulos com código em azul e os parciais em amarelo. 16 módulos descartados ficam fora de todas as contas.

De onde vêm os dados: a lista de módulos é docs/status/modulos-planejados.txt; o gerador procura um arquivo Rust de mesma pasta e mesmo nome em kernel/src, ou o arquivo declarado em [correspondencias] no components.toml. Parciais e fora da conta são declarados nas tabelas [parciais] e [fora_do_escopo].
